# חלק א׳ — מה שחדש לגמרי

## §1 🆕 יומן העסק / האוהד (Activity Log)

### מה קיים היום
**רק היסטוריית מיילים.** `recipientEmailHistoryHtml` שולף מ־`messageBroadcastHistory` (10 שידורים אחרונים) ומציג נושא + תאריך. זה הכל.

**מה לא מתועד בשום מקום:** מי אישר עסק ומתי · אילו בקשות אושרו/נדחו ומה היה לפני ואחרי · אילו שדות המנהל ערך בעצמו · החלטות תגיות וקטגוריות · עיגונים · עריכות לבבות · **שליחות ידניות (WhatsApp/מייל בודד)** · הערות מנהל.
`adminNote` קיים רק על `members` והוא שדה יחיד שנדרס בכל עדכון — לא היסטוריה.

### מודל הנתונים
תת־אוסף לכל ישות:
```
businesses/{bizId}/activity/{autoId}
members/{memberId}/activity/{autoId}
```
מבנה רשומה:
```js
{
  type: 'note'|'status'|'changeRequest'|'changeDecision'|'adminEdit'
      |'tagDecision'|'anchor'|'sectionFlag'|'hearts'|'email',
  title: string,        // "אושרה בקשת תגית שנייה"
  detail: string,       // "מוסכים וחלקי חילוף נוספה כתגית ראשית"
  field:  string|null,  // 'phone' / 'hours' / 'likesOverride'
  before: any|null,
  after:  any|null,
  actorUid:  string|null,
  actorName: string,    // "רמי כהן" / "בעל העסק" / "אוטומטי"
  source: 'admin'|'owner'|'system',
  createdAt: serverTimestamp()
}
```
**תת־אוסף ולא מערך על המסמך** — היומן גדל בלי הגבלה. התצוגה קוראת `orderBy('createdAt','desc').limit(5)` ומרחיבה **בתוך אותו כרטיס** בלחיצה (בלי ניווט).

### פונקציית העזר — קריטית
```js
async function logActivity(collectionName, entityId, entry) { ... }
```
**חייבת להיקרא מכל אחת מהפעולות הבאות.** בלעדיה התיעוד ייצא חלקי, וזה גרוע מכלום:

| קוראים מ־ | type | מה נרשם |
|---|---|---|
| `approveBiz` / `rejectBiz` / `deleteBiz` | `status` | אישור, דחייה, מחיקה |
| `approveFan` / `rejectFan` / `deleteFan` | `status` | + הקצאת מספר חבר וקוד כניסה |
| כתיבת `pendingChanges` (מדשבורד העסק) | `changeRequest` | רשימת השדות שהתבקשו |
| `approveChanges` / `rejectChanges` | `changeDecision` | לכל שדה: before → after |
| `saveSectionUpdates`, `saveBizSec1..5`, `saveFanDetails` | `adminEdit` | שם השדה + before/after |
| `approveTagSecondSuggestion`, `rejectTagSecondSuggestion`, `approveAlsoCatSuggestion`, `confirmMapTagSuggestion` | `tagDecision` | איזו תגית, מה הוחלט |
| `bumpSlot` / `saveAnchor` / `removeAnchor` | `anchor` | סקשן, מיקום, סוג עיגון, מחליף |
| `applySectionUpdate` (`activateSectionFlag`, `clearSectionFlag`, `toggleDealsSection`) | `sectionFlag` | איזה דגל, לכמה זמן |
| `activateLikesOverride` / `clearLikesOverride` | `hearts` | before → after + תוקף |
| Worker `/send-broadcast-email` + `sendBizWA`/`sendBizMail`/`sendFanWA`/`sendFanMail` | `email` | נושא, ערוץ, אוטומטי או ידני |
| כפתור "הוספה ליומן" בממשק | `note` | טקסט חופשי של המנהל |

### תצוגה
בעמודה השמאלית של כרטיס העסק ושל כרטיס האוהד — **פאנל כחול אחד** שמכיל: מד סקירה · `הסרה מהאינדקס` · שדה כתיבת הערה עם כפתור צהוב `הוספה ליומן` · ציר זמן של 5 הרשומות האחרונות · `הצגת היומן המלא` שמרחיב במקום.
צבע הנקודה בציר: צהוב = הערת מנהל · כחול בהיר = החלטה · לבן שקוף = פעולה אוטומטית.

## §2 🆕 מרכז לבבות (`8 מרכז לבבות.dc.html`)

### מה קיים היום
4 שדות על מסמך העסק: `likedBy[]` (מערך מזהי אוהדים), `likesOverride`, `likesOverrideUntil`, `likesOverrideSetAt`.
2 פונקציות: `activateLikesOverride`, `clearLikesOverride` — נגישות **רק** מתוך בלוק "סימוני סקשן" בכרטיס עסק בודד.
**אין:** מסך ריכוז · דרך לראות מי בעריכה · התראה על עריכה שפגה · תיעוד מי ערך.

### הטבלה
שורה לעסק, והעמודות:
- `אמיתי` = `likedBy.length`
- `מוצג` = `likesOverride ?? likedBy.length`
- `פער` = ההפרש (מודגש בכתום כשגדול)
- `תוקף` = `likesOverrideUntil` עם ספירה לאחור / "קבועה · בלי תוקף" / "אין עריכה"

**סינון:** הכל · עריכה פעילה · פגה בשבוע · בלי עריכה · אפס לבבות
**מיון:** הכי הרבה מוצגים · הכי הרבה אמיתיים · **הפער הגדול ביותר** · העריכה שפגה ראשונה · הכי מעט
**עריכה בשורה:** מספר מוצג + לכמה ימים (ריק = קבועה) → `שמירה` · `חזרה למספר האמיתי`
**בולק:** בחירה מרובה → הארכת תוקף ב־30 יום · חזרה למספר האמיתי
**פאנל צד:** עריכות שפגות בקרוב — "184 → יחזור ל־47 ב־06.08"

### גם בכרטיס העסק
בלוק `💙 לבבות` בתוך "המיקום באינדקס" שמציג **גם אמיתי וגם מוצג**: `184 · אמיתי 47 · מוצג 184 עד 31.08`.
היום הכרטיס מציג רק את המוצג — מנהל לא יודע שהוא מסתכל על מספר שנערך.

### 🆕 סקשן `mostLoved` — 💙 הכי אהובים
**מה יש היום:** `SECTIONS` מכיל 5: `featured`, `new`, `deals`, `online`, `everyone`.
**להוסיף:**
```js
{ key:'mostLoved', label:'💙 הכי אהובים', type:'section' }
```
+ רשומה ב־`SECTION_DESC`. `ELIGIBLE_FILTER` — אין הגבלה (כל עסק מאושר כשיר, כמו `everyone`).
**הסדר נקבע לפי `likesOverride ?? likedBy.length`** בסדר יורד.
**השלכה שחייבים להיות מודעים לה:** עריכת לבבות משנה גם את הדירוג בסקשן, לא רק את המספר על הכרטיס. זו הסיבה שעמודת "פער" חייבת להיות גלויה.

### מה **לא** שייך לכאן
מי נתן לב לאיזה עסק ומי נתן הכי הרבה — **שייך למרכז הנתונים**. מרכז הלבבות הוא מסך פעולות. `likedBy[]` כבר מכיל את המזהים.

**דרוש שדה חדש:** אין. דרוש `logActivity` מסוג `hearts`.

## §3 🆕 מרכז נתונים (`9 מרכז נתונים.dc.html`) + שכבת מדידה

### ⚠️ האזהרה המרכזית
**כמעט כל מה שהמסך מציג לא נמדד היום.** אין מעקב sessions, אין ספירת כניסות, אין לוג קליקים.
מה שכן קיים: `clicks` (מונה מצטבר בודד על עסק, בלי היסטוריה), `likedBy[]`, ו־`submittedAt`/`approvedAt`.
**בלי שכבת המדידה, המסך יראה מספרים שאין להם מקור.** במסך עצמו כל מדד כזה מסומן בכתום.

### 🆕 אוסף `events`
```js
events/{autoId} = {
  type: 'pageView' | 'bizImpression' | 'bizClick' | 'bizContact'
      | 'heart' | 'gateBlock' | 'landingBlockClick' | 'formOpen' | 'formSubmit',
  bizId:     string|null,
  memberId:  string|null,   // null לגולש לא מחובר
  sessionId: string,
  path:      string|null,   // ל-pageView
  referrer:  string|null,   // 'whatsapp' | 'instagram' | 'direct' | 'email'
  device:    'mobile'|'desktop',
  blockId:   string|null,   // ל-landingBlockClick: 'tile1' | 'blueBox' | 'yellowBox'
  channel:   string|null,   // ל-bizContact: 'whatsapp'|'phone'|'email'|'website'
  createdAt: serverTimestamp()
}
```

### 🆕 אגרגציה יומית — חובה
בלי זה המסך יסרוק מיליוני רשומות בכל טעינה.
```
stats/daily/{YYYY-MM-DD}                    // כלל־פלטפורמה
businesses/{bizId}/statsDaily/{YYYY-MM-DD}  // לכל עסק
```
Cloud Function מתוזמנת (או Worker cron) שמצטברת מ־`events` פעם ביום.

### 🆕 `lastSeenAt` על `members`
בלעדיו אין "נכנסו ב־30 יום" ואין "318 לא נכנסו מאז האישור".

### 🔧 `clicks` הקיים
מונה מצטבר בלי היסטוריה. **לשמור אותו**, אבל להוסיף פירוק יומי — אחרת אין מגמות ואין השוואת תקופות.

### ששת הטאבים
1. **סקירה רוחבית** — 6 KPI · גרף כניסות ולחיצות לפי יום · משפך הצטרפות · **8 קוביות אינדיקציה, אחת לכל אזור בדשבורד**, כל אחת לחיצה שעוברת לאזור
2. **עסקים** — טבלה: חשיפות · לחיצות · המרה · לבבות · פניות · עדכון אחרון · באילו מיקומים מעוגן. פילוח לפי קטגוריה. בלוק "דורש תשומת לב" שמצליב נתונים
3. **אוהדים ופלטפורמה** — הרשמות לפי שבוע · איך אומתו · האוהדים הפעילים ביותר
4. **לבבות ומעורבות** — מי נותן הכי הרבה · לאיזה עסקים נותנים · מדדי מעורבות (לב לכל 100 לחיצות)
5. **קטגוריות ותגיות** — לכל קטגוריה: עסקים · לחיצות · **לחיצות לעסק** (ביקוש אמיתי, לא גודל) · לבבות · תגיות · מיקומים מעוגנים
6. **פלטפורמה ודף נחיתה** — **מסלול הגולש** (נכנסו → גללו → לחצו על עסק → **נחסמו** → פתחו טופס → שלחו) · מאיפה הגיעו · לחיצות לפי בלוק בדף

**המדד הכי חשוב בטאב 6:** `gateBlock` — כמה גולשים לא־מחוברים נחסמו על כרטיס עסק, וכמה מהם המשיכו להרשמה. זה מה שמראה אם החסימה ממירה או מבריחה.

## §4 🆕 סיווג הפעולה הנדרשת — `classifyAction()`

### מה יש היום
אין סיווג. צ'יפים לא־מדורגים באותו גוון (`✏️ שינויים`, `🏷️ בקשה ממתינה`, `💬 כתבו לנו`), ו־`bizHasAnyPendingChange` מחזיר bool אחד בלי לומר *מה*.

### הפונקציה
```js
classifyAction(entity) → { primary: string, treatments: string[] }
```
**כל המסכים קוראים לה.** שלא יהיו שני מימושים — זה בדיוק מה שגורם לשורה ולכרטיס לסתור זה את זה.

| primary | תנאי |
|---|---|
| `עסק ממתין לאישור` | `businesses.status === 'pending'` |
| `אוהד ממתין לאישור` | `members.status === 'pending'` |
| `בקשה מבעל העסק` | עסק מאושר עם משהו ממתין |
| `כרטיס חסר באינדקס` | `healthScore < 100` |
| `מאושר · אין פעולה` | אין שום דבר ממתין |

| treatment | תנאי |
|---|---|
| `שינוי פרטים` | `pendingChanges` |
| `בקשת תגית` | `tagSuggestion` \|\| `tagSecondSuggestion` |
| `בקשת קטגוריה` | `alsoCategorySuggestion` \|\| `alsoCategoryNote` |
| `כתבו לנו` | `note && !noteHandled` |

### כלל צבע מחייב
הצבע **לא** מסמן דחיפות או סוג.
`#0A2A66` מלא = תגית ראשית · `#EEF2FA` = סוגי טיפול · `#FFFBEB`/`#B54708` = **בלעדית ל"חסר / לא אומת"**.
הטקסט אומר מה לעשות, לא הצבע.

**מינוח:** "דורש טיפול" הוחלף ב־**"בקשה מבעל העסק"**. "דורש פעולה" הוא המטרייה שמכילה את כולם — שני הביטויים נשמעו זהים בעברית.

# חלק ב׳ — שינויי התנהגות

## §7 🔧 אישור ודחייה פר־בקשה

**היום:** `approveChanges` כותב את **כל** `pendingChanges` במכה אחת; `rejectChanges` מנקה את כולם. אין דרך לאשר את שינוי הטלפון ולדחות את שינוי השעות.

**צריך:**
```js
approveChangeField(bizId, field, valueOverride)  // מוחק מפתח בודד מ-pendingChanges וכותב אותו
rejectChangeField(bizId, field)                   // מוחק מפתח בודד בלי לכתוב
```
`valueOverride` — כי המנהל יכול **לתקן את הערך לפני האישור** (השדה בממשק הוא קלט, לא טקסט).

**בממשק:** סרגל "שיפוט מהיר" בראש כרטיס העסק, נפתח/נסגר. **כל בקשה שורה מלאה ברוחב הכרטיס:** שם השדה · *לפני מחוק → שדה קלט* · `אישור` / `דחייה` / `לשלב N ←`.
בבקשת תגית גם: `אישור כתגית` / `מיפוי לקיימת` / `לניהול התגיות ←`.

**הוסר במפורש:** "אישור כל הבקשות" ו"דחיית הכל" — בשום מקום במסך. כל בקשה נשפטת בנפרד.

## §8 🔧 מרכז הודעות — שני תהליכים נפרדים

**היום** שני התהליכים קיימים אבל מוצגים כרשימת מקטעים מקופלים:
- `broadcastTabHtml` + `sendBroadcastNow` → POST ל־Worker `/send-broadcast-email`, שליחת שרת לכל הקהל
- `manualSenderHtml` + `sendManualAdhoc` → צ'קבוקסים ואז `window.open` לוואטסאפ/mailto, **אחד־אחד, בלי שרת**

**בעיצוב:** מתג `שידור המוני` / `נמענים נבחרים` שבאמת מחליף את גוף המקטע, כולל הכיתוב והכפתורים. חובה שה־UI יאמר את ההבדל — אחרת המשתמש חושב שהוא שולח לכולם והמערכת פותחת לו 40 חלונות.

**להוסיף:**
- 🆕 **תצוגה מקדימה של המייל** עם המשתנים מוחלפים בנתוני הנמען הראשון. זה מה שמונע לשלוח ל־1,268 איש מייל עם `{name}` גלוי
- 🆕 **שליחה מחדש לנכשלים** — `results` כבר נשמר עם `status:'failed'` לכל נמען, אבל אין שום פעולה. "17 נכשלו" צריך להיות כפתור
- 🆕 **מייל בדיקה אליי** לפני שליחה אמיתית
- 🎨 **"נשלח ע״י רמי כהן"** — `sentByUid` נשמר ולא מוצג
- 🎨 חיפוש לפי שם בבחירת הקהל
- 🎨 שני טאבים ראשיים: `שליחה עכשיו` / `התבניות הקבועות · 7`, וסינון התבניות בצ'יפים

**לשקול (לא עוצב):** הסרה מרשימת תפוצה. אין שדה כזה היום — חשיפה משפטית. וגם מונה פתיחות אם Brevo מחזיר אותו.

## §9 🔧 סבב אוטומטי — החישוב הנכון
גודל הסבב = `מאושרים − מעוגנים בסקשן הזה`, לא סך המאושרים.
`previewStripHtml` כבר עושה את זה נכון (`autoPool = autoOrderFor(tab).filter(b => !anchoredIds.has(b.id))`) — רק צריך **להציג את המספר הנכון** בממשק.
עסק מעוגן לא מופיע גם בסבב, ואותו עסק לא ממלא שני מיקומים באותו יום.

# חלק ד׳ — עיצוב בלבד (בלי backend)

## §13 🎨 מרכז המשימות מחליף את `homeTabHtml`
**היום:** 4 לשוניות (`אוהדים ממתינים` / `עסקים חדשים` / `עסקים לטיפול` / `בריאות פרופיל`), כל אחת מחביאה את השלוש האחרות.
**במקום:** 4 קוביות פילוח שמראות הכל במקביל, כולל פירוט סוגי הטיפול בתוך הקובייה, ומתחתן **רשימה אחת מאוחדת** של עסקים ואוהדים יחד.
**פתיחה בפאנל חצי־עמוד:** לחיצה על **כל השורה** (לא רק כפתור) פותחת את הכרטיס בפאנל מעוגן על חצי מסך. הרשימה נשארת גלויה מאחור, סגירה מחזירה לאותו מקום. **אין ניווט לעמוד אחר** — זה היה הכשל בגרסה קודמת.
**סינון בשני צירים:** צ'יפים לפי סיווג הפעולה + שורת סינון לפי תכונות (חיפוש · מיון · תקופה · קטגוריה · סוג).

## §14 🎨 חמשת השלבים
- כל שלב סגור מציג **שורת תקציר**: "15% על טיפול תקופתי · מימוש בחנות · הטבה אחת מתוך 3"
- **לחיצה על השורה** פותחת את השלב (חץ `›` ⟷ `⌄`)
- בשלב פתוח — **כל שדה בשורה עם כפתור `עריכה` צמוד**. שדה שיש עליו בקשה פתוח כבר כקלט עם "היה X" ו`שמירה`
- מד סקירה `n/4` בשלושה מקומות **מסונכרנים**: בשורת הרשימה · 4 פסים ליד כפתור האישור · צ'קבוקס בכל כותרת שלב

## §15 🎨 כותרת ההטבה — תצוגה מקדימה ברוחב האמיתי
`ensureFitsCard` כבר מודד 151px בפונט `700 11px Heebo`. במקום תווית "✓ נכנס / ⚠️ חורג" — **קופסה ברוחב 151px שמציגה את הטקסט בפועל**. רואים את התוצאה, לא קוראים עליה.

## §16 🎨 סקשנים — קריאוּת
המנגנון שלם (10 מיקומים, `fixed`/`temp`, `next`+`handoverAt`, `settings/sectionAnchors`). מה שחסר:
- כל שורת מיקום אומרת הכל: מספר · עסק · סוג העיגון עם ספירה לאחור · **מה יקרה אחר כך** · פעולות
- **פאנל "מה מסתיים בקרוב"** שמפרט **מי המחליף, איזה סוג עיגון, ועד מתי** — לחיצה על שורה קופצת למיקום
- **תצוגה מקדימה** של דף הבית כפי שייראה היום
- **"איך עובד כל סקשן"** — הסבר לכל אחד מ־6 הסקשנים + כלל הקטגוריות + מילון (עיגון קבוע / זמני / מחליף מתוזמן / סבב אוטומטי). התוכן קיים ב־`SECTION_DESC` אבל לא נגיש בזמן העבודה
- **בכרטיס העסק:** בלוק "המיקום באינדקס" — שורה לכל מקום שהעסק מופיע בו, מתג `קבוע/זמני`, הסרת עיגון, ו`לשורה בסקשן` לעבודת התזמון

## §17 🎨 ניהול תגיות
- **תור הבקשות:** שורה מלאה לכל בקשה, עם **שם התגית כשדה עריכה** (תיקון הקלדה לפני אישור), בורר קטגוריה, ו־`הוספה לקטלוג` / `מיפוי לקיימת` / `דחייה` / `לעסק ←`
- **מיון וסינון בשני המקומות:** בקשות לפי חדש/ישן/קטגוריה + סוג הבקשה; קטלוג לפי הכי הרבה עסקים / הכי מעט / **לא בשימוש קודם** / אלפבית, וסינון בשימוש/לא בשימוש/עסק אחד
- מונה השימוש **לחיץ** ונפתח לרשימת העסקים

## §18 🎨 עקביות רוחבית — חובה
- **סרגל ניהול מימין**, נפתח ונסגר (236px ↔ 64px, האייקונים נשארים). **אייקוני Lucide, לא אמוג'י**
- **מרכז נתונים אחרון בסרגל, אחרי קו מפריד**
- **אותם מונים בכל המסכים** — badge שמופיע בעמוד אחד ונעלם באחר הוא באג
- **כל מונה נגזר ממקור אחד** בלוגיקה. אסור להקליד את אותו מספר פעמיים — זה הכשל שחזר הכי הרבה פעמים בעיצוב
