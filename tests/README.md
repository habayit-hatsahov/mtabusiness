# בדיקות — Yellow Zone

שתי חבילות בדיקה שרצות **בהרצה אמיתית**, לא בקריאת קוד. נכתבו ב-§417.

## למה זה קיים

`firestore.rules` חי בפרודקשן ושומר על נתונים אמיתיים. עד §417 כל שינוי בו נבדק בעין
בלבד — כלומר לא נבדק. הבדיקות כאן מריצות את הקובץ **כפי שהוא בריפו** מול אמולטור
Firestore אמיתי, ומנסות לשבור אותו מזוויות של תוקף.

## הרצה

```
cd tests
npm install
npm run test:banner     # לא דורש כלום מעבר ל-Node
npm run test:rules      # דורש Java
```

### Java לבדיקות החוקים

אמולטור Firestore רץ על Java. אם אין Java ב-PATH, אפשר להשתמש בזו שמגיעה עם
Android Studio, בלי להתקין דבר:

```
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
export PATH="$JAVA_HOME/bin:$PATH"
```

## מה מכוסה

**`rules.test.js` — 32 בדיקות.** תת-האוסף `businesses/{id}/messages` (§417): התחזות
בין הצדדים, עריכת תוכן שנשלח, סימון "נקרא" ע"י הצד הלא-נכון, קריאה ע"י זר או
אנונימי, גבולות אורך הטקסט, שדות זרים; שדות הסיכום על מסמך העסק; ומסמך המתג
`settings/appLaunch`.

**`banner.test.js` — 19 בדיקות.** `app-banner.js` מול DOM אמיתי (jsdom): שלושת
המנעולים, זיהוי מערכת ההפעלה, הפרדת הקהלים, זכירת סגירה, וניסיון הזרקת HTML דרך
נוסח שהמנהל עורך.

## שתי מלכודות שנתפסו כאן בפועל, ולא לחזור עליהן

1. **כתיבת אותו ערך אינה שינוי.** `diff().affectedKeys()` לא מכיל שדה שנכתב עם ערכו
   הקיים — בדיקה שכותבת `status:'approved'` על מסמך שכבר approved אינה בודקת כלום
   ו"עוברת" תמיד.
2. **jsdom 30 מתעלמת מ-`userAgent` בבנאי.** כל בדיקות זיהוי המכשיר רצו על זהות שגויה.
   יש בקובץ שורה שמפילה את הריצה אם הדריסה הידנית לא תפסה — אל תסירו אותה.
